# Plan 01: Build Gap Analysis Tooling

## Objective

Create the gap analysis script that compares function coverage at three tiers:
1. Library exports (nm symbols) vs libErator APIs (apis_clang.json)
2. libErator APIs vs constraints (conditions.json)
3. Constraints vs generated schema (.proto)

Purpose: This tooling is the foundation for all Phase 1 analysis - without it, we cannot measure gaps.

Output: `scripts/gap_analyzer.py` that produces JSON reports per target.

## Context

@.planning/phases/01-baseline-gap-analysis/01-RESEARCH.md
@src/proto_generator.py

Key data sources discovered in research:
- `analysis/<lib>/work/apipass/apis_clang.json` - JSONL format, one function per line
- `analysis/<lib>/work/apipass/conditions.json` - JSON array of function metadata
- Library symbols via `nm -D --defined-only` for .so or `nm --defined-only` for .a
- Schema functions via grep for `_Params {` pattern

Create bash script that extracts exported function symbols from a library file.

Requirements:
- Accept library path as argument
- Auto-detect if .so (shared) or .a (static)
- For .so: use `nm -D --defined-only --extern-only` and filter for "T" (text) symbols
- For .a: use `nm --defined-only --extern-only` and filter for " T " symbols
- Output one function name per line to stdout
- Exit 1 if library not found or nm fails

Example usage:
```bash
./scripts/extract_symbols.sh /path/to/libcjson.so
./scripts/extract_symbols.sh /path/to/libcjson.a
```

<task type="auto">
  <name>Task 2: Create gap analyzer Python script</name>
  <files>scripts/gap_analyzer.py</files>
  <action>
Create Python script implementing three-tier gap analysis as specified in research.

Requirements:
1. CLI interface with argparse:
   - `--library` - library name (e.g., cjson)
   - `--lib-path` - path to compiled library (.so or .a)
   - `--apis-path` - path to apis_clang.json
   - `--conditions-path` - path to conditions.json
   - `--proto-path` - optional path to generated .proto schema
   - `--output` - output JSON report path
   - `--verbose` - print progress to stderr

2. Function extraction methods:
   - `extract_library_symbols(lib_path)` - uses subprocess to call extract_symbols.sh
   - `load_apis_clang(path)` - parses JSONL (one JSON object per line), extracts function_name
   - `load_conditions(path)` - parses JSON array, extracts function_name from each entry
   - `extract_schema_functions(proto_path)` - regex for `message (\w+)_Params {`

3. Gap analysis:
   - gap_tier1: library_symbols - api_functions (functions not analyzed by libErator)
   - gap_tier2: api_functions - condition_functions (analyzed but no constraints)
   - gap_tier3: condition_functions - schema_functions (constraints but excluded from schema)

4. Output JSON structure:
```json
{
  "library": "cjson",
  "generated_at": "2026-01-21T...",
  "counts": {
    "library_exports": 78,
    "liberator_apis": 78,
    "with_constraints": 60,
    "in_schema": 55
  },
  "gaps": {
    "tier1_not_analyzed": ["func1", "func2"],
    "tier2_no_constraints": ["func3"],
    "tier3_excluded_schema": ["func4"]
  },
  "coverage_pct": {
    "api_coverage": 100.0,
    "constraint_coverage": 76.9,
    "schema_coverage": 91.7
  }
}
```

5. Error handling:
   - If lib_path is None or doesn't exist, skip tier1 (set library_exports to null)
   - If conditions.json is empty (0 bytes), set with_constraints to 0
   - If proto_path not provided, skip tier3

Use pathlib for paths, subprocess for shell commands. Follow existing code conventions from src/*.py.
  </action>
