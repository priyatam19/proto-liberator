# Plan 02: Analyze cJSON Function Coverage Gaps

## Objective

Run gap analysis on cJSON library and generate deliverable reports.

Purpose: cJSON is the best-performing target (76.99% function coverage). Understanding its gaps will establish patterns for other targets and validate the analysis tooling.

Output: Gap report (JSON + Markdown) documenting which cJSON functions are missing and why.

## Context

@.planning/phases/01-baseline-gap-analysis/01-01-PLAN.md (provides gap_analyzer.py)
@analysis/cjson/work/apipass/apis_clang.json
@analysis/cjson/work/apipass/conditions.json

cJSON baseline (Jan 19, 2026):
- Function coverage: 76.99% (CMP mode)
- Branch coverage: 22.19%
- Expected ~78 functions based on apis_clang.json

<task type="auto">
  <name>Task 1: Locate cJSON library and run gap analysis</name>
  <files>.planning/phases/01-baseline-gap-analysis/reports/cjson_gap_report.json</files>
  <action>
1. Create reports directory:
```bash
mkdir -p .planning/phases/01-baseline-gap-analysis/reports
```

2. Find cJSON library path (check common locations):
   - `analysis/cjson/build/` or similar
   - OSS-Fuzz build artifacts if available
   - If not found, run without library symbols (tier1 will be skipped)

3. Check for existing generated schema:
   - Look in `workdir/campaigns/` for any cjson campaign with generated .proto
   - Or generate fresh schema for comparison

4. Run gap analyzer:
```bash
python3 scripts/gap_analyzer.py \
  --library cjson \
  --apis-path analysis/cjson/work/apipass/apis_clang.json \
  --conditions-path analysis/cjson/work/apipass/conditions.json \
  --output .planning/phases/01-baseline-gap-analysis/reports/cjson_gap_report.json \
  --verbose
```

If library path found, add `--lib-path /path/to/libcjson.a`.
If schema found, add `--proto-path /path/to/schema.proto`.
