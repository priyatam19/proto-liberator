## Why 0.69% Coverage?

libaom's extremely low coverage stems from three architectural factors:

### 1. Codec Initialization Sequence Complexity

AV1 encoding/decoding requires a strict initialization sequence:
```
aom_codec_enc_init_ver() / aom_codec_dec_init_ver()
  -> codec context allocated with specific config
  -> aom_codec_encode() / aom_codec_decode()
  -> aom_codec_destroy()
```

The fuzzer cannot call encoding/decoding functions without a properly initialized context. Random protobuf data will cause immediate rejection at guard checks.

### 2. State Machine Dependencies

libaom is inherently stateful:
- Encoder requires valid `aom_codec_enc_cfg_t` configuration
- Decoder expects valid AV1 bitstream data
- Control functions (`aom_codec_control`) require active codec instance
- Image functions require allocated `aom_image_t` structures

Without understanding these state transitions, the fuzzer cannot reach internal codec logic.

### 3. Macro-Generated Function Gap

196 of 243 APIs (80.7%) are `aom_codec_control_typechecked_*` functions:
- These are C preprocessor macro expansions
- libErator's LLVM-based analysis sees them as separate functions
- But static analysis cannot derive their constraints from macro definitions
- Example: `aom_codec_control_typechecked_AV1E_SET_TILE_COLUMNS`

## Recommendations

### Short Term (This Phase)

1. **Focus on 47 constrained functions only**
   - Generate schema for these functions
   - Accept 19% as realistic upper bound for Phase 1

2. **Prioritize stateless functions**
   - `aom_codec_version*`, `aom_obu_type_to_string`, `aom_uleb_*`
   - These can be fuzzed without initialization

3. **Add image utility coverage**
   - `aom_img_alloc`, `aom_img_free`, `aom_img_set_rect`
   - Standalone allocation/deallocation patterns

### Medium Term (Phase 2-3)

4. **Manual constraint generation for codec_control**
   - Analyze `aom_codec.h` macros
   - Generate synthetic constraints for control functions
   - Group by control ID type (int, struct pointer, etc.)

5. **Initialization sequence templates**
   - Create fixed encoder/decoder init sequences
   - Use as seed corpus preamble

### Long Term (Phase 4-5)

6. **Stateful fuzzing harness**
   - Track codec state (uninitialized/encoding/decoding)
   - Allow control functions only after init
   - Reset state between sequences

7. **Bitstream-aware mutation**
   - Generate valid AV1 OBU sequences
   - Feed to decoder for deeper coverage
